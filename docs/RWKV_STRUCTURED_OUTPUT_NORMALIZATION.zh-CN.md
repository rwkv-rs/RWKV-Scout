# RWKV 结构化输出格式归一化

## 目的

该层只处理 RWKV 结构化请求返回值的传输外壳。它位于模型返回与协议校验之间，不参与工具选择、查询生成、证据判断或最终答案生成。

允许的无损格式只有：

1. 一个完整 JSON 对象；
2. 请求已经预填 `{` 时返回的对象尾部；
3. 可选的 `Assistant:` 与一个 JSON Markdown fence；
4. Evidence Extractor 的单元素对象数组。

以下输出不会被修复：多个 JSON 对象、JSON 前后夹杂解释、单引号 Python 字典、缺失引号或括号、非法转义、多元素数组、未知工具、错误参数。它们继续进入现有的一次同温度 RWKV 协议重试。

最终答案不经过该层，也不做删改或重写。

## Tool-call 字段归一化

JSON 对象解析成功后，tool-call adapter 只把同一个调用的常见表示转换成内部唯一结构：

- `name` / `tool_name` / `action` / `tool` / `function.name` → `name`
- `arguments` / `args` / `parameters` / `function.arguments` → `arguments`
- 单元素 `tool_calls` → 一个内部调用
- 仅含一个对象值的函数名包装（例如 `{"web_search":{"query":"RWKV"}}`）→ `name` + `arguments`

转换后内部结构固定为 `{"contract": "rwkv.ecra.runtime.tool-call","name":"...","arguments":{...}}`。

转换层没有其他职责：不选择工具、不补充或改写参数、不判断证据、不决定重试，也不处理最终答案。多个工具调用或互相冲突的别名无法无损转换为项目的单调用格式，因此由转换前的协议校验拒绝；这项校验不属于格式转换，也不会替 RWKV 选择其中一个。

这仍然只是格式兼容，不验证工具是否适合问题，也不修改查询与参数内容。

## Round 26 Trace 审计

对 Round 26 全部 5,043 次非最终结构化模型返回进行重新解析：

| 类型 | 数量 | 处理 |
|---|---:|---|
| 完整 JSON 对象 | 4,915 | 原样解析 |
| 单元素对象数组 | 2 | 仅去除数组外壳 |
| 无法形成完整 JSON | 126 | 不修复，保持协议错误 |

Planner、Planner Recovery 和 Task Plan 共 699 次返回全部是完整 JSON 对象。格式偏差集中在 Page Evidence：2 次单元素数组；其余失败主要是输出截断、未闭合字符串、非法转义或控制字符，不属于可安全转换的格式问题。

126 次无效返回包括 92 次未闭合字符串、14 次非法控制字符、13 次非法转义和 7 次缺少 JSON 分隔符；其中 48 次在既有一次重试后仍无效。这些属于生成完整性问题，不能由安全的外壳转换推断缺失内容。

因此该层是兼容边界，不是新的决策模块，也不是解决证据质量上限的主要机制。

## 可观测字段

结构化阶段记录：

- `protocol_input_format`
- `protocol_normalized`

原始模型输出仍完整保留在 Trace 中，可以逐项核对转换前后是否只改变外壳。
